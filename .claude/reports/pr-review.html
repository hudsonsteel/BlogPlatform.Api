Good practices noticed

Patterns that match CLAUDE.md — keep doing these.

  • Dependency direction holds. No using BlogPlatform.Infrastructure in Domain or Application; no using Microsoft.EntityFrameworkCore in Domain; no using BlogPlatform.Application in Domain. Verified by grep.
  • Validators live next to their entities. BlogPostValidator sits in BlogPost.cs; CommentValidator in Comment.cs.
  • Notification pattern is correct. Entity.Id has no default value; EntityConfiguration<T> applies ValueGeneratedOnAdd() so EF Core's GuidValueGenerator runs at insert. New entities have Id = Guid.Empty until SaveChanges — exactly what the change tracker needs to mark them Added.
  • CQRS-lite split is real. IBlogPostRepository.GetByIdAsync is the single full-aggregate loader (Include(Comments).AsSplitQuery()); IBlogPostQueries.ListAsync projects directly to PostListItemDto. Two separate Infrastructure classes — exactly as documented.
  • Use cases follow the prescribed pattern uniformly. Primary ctor for DI; *BuilderMap.From(...) builds entities; await entity.ThrowIfInvalidAsync(validator, ct) for validation; Result.Failure(Error.NotFound(...)) for expected outcomes. Zero catch blocks under src/.
  • Tests follow the playbook. File paths mirror source; <ClassUnderTest>Tests naming; Method_State_ExpectedBehavior; // Given / // When / // Then; mocks only for interfaces from Domain/Repositories, Application/Common/Queries, and FluentValidation.IValidator<T>.
  • GlobalExceptionHandler routes through IProblemDetailsService.TryWriteAsync, and Program.cs:38-44 stamps a fresh GUID traceId on every error — the 5-field ProblemDetails contract is honored.
